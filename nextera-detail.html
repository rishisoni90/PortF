Challenge

The request flow was slow, serial, and brittle

When a user asked for events in an organization, the request had to pass through multiple external and internal components. The flow depended on UIQ, a third-party service, which interacted with the Samer T-Meter. The meter then processed the request and returned the response back to UIQ before the data could be enriched and returned to the user. That design worked, but it created serious processing bottlenecks at scale.

What was happening
  • Single-threaded, sequential handling caused long queues when event volume rose.
  • Large event batches were being generated in a way that amplified latency and retry cost.
  • UIQ and the meter dependency chain introduced network and orchestration delays.
  • Response handling was not resilient enough for high-volume outages or partial failures.
Why it mattered
  • Generating 1 million events previously took around 6 hours, creating SLA risk for downstream consumers.
  • Business waits were growing with each spike in request volume or external dependency delay.
  • Slow processing blocked user experience and reduced operational confidence.
  • Operational teams were forced to treat event generation as a heavy batch task instead of a responsive workflow.
Architecture

The design flow behind the request

The system sits on a hybrid orchestration model: the user triggers an organizational event request, UIQ acts as the third-party intermediary, and Samer T-Meter handles the actual event retrieval and validation. Once the meter responds, the orchestration layer normalizes the response and exposes it back to the platform.

What changed

The optimization focused on flow, concurrency, and orchestration

⚡

Thread scaling

I increased thread capacity and concurrency so the system could process multiple event-generation requests at the same time instead of queuing them behind a single blocking path.

🔁

Async processing

I converted the blocking request flow to asynchronous execution so the service no longer waited idly for each UIQ-to-meter interaction to finish before moving to the next task.

🧠

Retry and timeout tuning

I reduced redundant payload handling, tightened retry behavior, and improved timeout logic so transient dependency failures did not cascade into long-running stalled batches.
